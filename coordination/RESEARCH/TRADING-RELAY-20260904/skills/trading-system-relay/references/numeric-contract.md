# 数值与语义防漂移合同

agent_id: CODEX | CANDIDATE

## 固定三类，分别管理

| 类别 | 应固定内容 | 变更方式 |
|---|---|---|
| 工程不变量 | schema、单位、时间语义、来源、权限、NO_TRADE、精确版本、重复执行等价 | 版本迁移 + 合同测试 |
| 随制度改变的规则 | 交易日历、板块/证券规则、涨跌幅、价格单位、费用、结算、停复牌 | 官方来源 + effective_from/to + 历史版本，不能永久硬编码 |
| 经验与预测参数 | 阈值、窗口、模型权重、漂移报警、滑点估计 | 事前训练/验证协议 + 样本外评估 + 审核，不按结果偷偷改 |

行情事实不是可任意固定的参数；固定的是“什么数、什么时间、什么单位、来自哪里、如何计算”。

## 每个数值的字典

建议复用现有市场语义合同，新增缺失字段时先版本化：

`metric_id, definition, formula_version, value, unit, scale, currency, sign_convention, null_reason, source_ref, source_field, event_time, receive_time, available_at, as_of, adjustment_method, corporate_action_version, aggregation_window, calendar_version, rule_version, quality_status, config_hash, evidence_ref`。

示例：成交量明确“股”或“手”；成交额明确“元”；资金净额注明正号含义和供应商算法版本；概率注明预测事件和期限，0.7 不能在交接中变成 70 再当作 70 倍。`null` 不得自动填 0；只观测到代理字段就标 `PROXY`，不能改名为真实资金或真实投资者身份。

价格与账务新接口优先用整数最小计价单位或 Decimal，舍入规则和舍入时点版本化；不要对既有 float 引擎宣称已经改为定点。统计结果按预先约定绝对/相对容差比较；金额、数量、事件 ID 和哈希应精确相等。跨平台回放若浮点不等，报告差异再决定容差，不能为了过测试临时放宽。

## 本次可机器验证的固定值

`replay-lock.json` 只适用于合成验证，不是 A 股生产规则包：

- `mode=research_only, no_trade=true`；
- `repeat_runs=2`；
- 合成输入事件数 `8`；
- `as_of=2026-01-31T23:59:59Z`；
- 所有 P2 Python 源码和合成 CSV 的 UTF-8/LF 内容哈希；
- 子进程超时 60 秒，CI 总超时 5 分钟；
- 13 个 JSON 工件的规范化内容完全一致；
- 未配置治理日历时模拟成交数必须为 0，并有明确拒绝原因；
- LearningPacket `authority_write=false`。

两次执行时间/机器名/挑战值放在外层 receipt，不参与确定性业务结果哈希。receipt 同时记录 Python 版本、操作系统、真实源码 commit、锁哈希与验证器哈希。引擎跨版本应使用新的锁，不自动更新黄金结果来迎合失败。

## 时间、周期与数据修订

1. 内部统一带时区时间，展示使用 Asia/Shanghai。接收时间不能替代事件时间，`available_at ≤ decision_time` 是回放准入必要条件。
2. 周线/月线未结束时只可标 provisional，不能拿最终周收盘数据指导周内历史决策。跨周期 join 取当时已可见版本。
3. 证券主表、退市股票、行业成分、财务报表、复权和公司行动也要 PIT，防止幸存者与未来信息污染。
4. 原始数据修订只追加：旧 hash → 新 hash、理由、来源、生效时间。保留历史运行引用的旧数据；新数据触发新实验，不覆盖旧答案。
5. 日历不能从“这天恰好有行情”推定；停牌、缺失、非交易日分别表达。T+1 按治理日历计算，不按电脑自然日或下一条行情。

## 三种漂移，不混成一个报警

| 漂移 | 例子 | 监测与处置 |
|---|---|---|
| 工程/语义漂移 | 字段改名、元变万元、规则包改变 | schema/单位/哈希差异；停止该路径，迁移后复验 |
| 输入分布漂移 | 流动性、波动率、行业样本改变 | 缺失率/分位数/PSI/KS 等候选监测；记录窗口、样本量、基准版本 |
| 预测关系/效果漂移 | 信号仍出现但后续收益关系改变 | 成熟标签后的 Brier、校准、收益成本、回撤、regime 分层，降级或弃权 |

PSI 0.1/0.25 不是普适金融定律；报警阈值需要数据、误报预算和时间依赖评估。标签没成熟时不能声称预测已经对错。不要用变化后的测试集反复挑模型。

## 验算与升级

每个策略登记 hypothesis_id、经济机制、方向、期限、基准、训练/验证/最终保留集、试验族数量、成本模型、失败条件。按时间切分，重叠标签需要合适 purging/embargo；block bootstrap 等方法的前提和 block 长度须披露。

检验收益之外，检查覆盖率、拒绝率、校准、成交可行性、容量、换手、交易成本和尾部风险。DSR/PBO 帮助校正多次试验挑赢家，不提供盈利认证。制度/牛熊/流动性周期分层；复杂模型必须有相对简单基线的样本外增量。

回测、影子、真实运行是分开的证据等级。新版本先 challenger，旧版 champion 冻结，差异可追溯后审核；不因论文或单轮收益升级。
