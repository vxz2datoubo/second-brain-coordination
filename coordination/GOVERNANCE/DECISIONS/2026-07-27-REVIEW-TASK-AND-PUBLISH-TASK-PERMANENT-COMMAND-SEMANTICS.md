# 永久治理决策：审查任务与发布任务的固定语义

- 决策日期：2026-07-27
- 父项目：Issue #31
- 状态：ACTIVE / PERMANENT_PROJECT_MEMORY
- 权威协议：`coordination/GOVERNANCE/GPT-TASK-REVIEW-AND-PUBLISH-COMMAND-SEMANTICS-v1.0.yaml`

## 用户口令：审查任务

以后用户说“审查任务”“审核任务”“验收任务”或同义短句，GPT必须：

1. 读取Agent完整报告，而不是只读摘要或完成声明；
2. 读取相关PR、提交链、变更文件、测试、回执、命令、失败、UNKNOWN、主动发现和主动扩展；
3. 对照远端真实代码与机器证据，不能把Agent自述当作事实；
4. 判断哪些成果可以直接接受，哪些可以整合，哪些需要GPT改良，哪些应删除或退回修改；
5. 判断哪些主动扩展有高价值，应继续拓展或吸收到下一轮任务；
6. 检查与项目整体架构、canonical、所有权、接口、依赖、节奏和安全边界是否协调；
7. 保存负面结果、反证和UNKNOWN，不得为了漂亮结论削弱测试或删除不利证据；
8. 形成明确的接受边界、修订边界、删除边界、拓展目标和系统级影响。

“审查任务”不是机械勾清单，不是只看数量，也不默认立即发布新任务。若用户同时要求发布，则必须先完成审查，再从审查结果发布。

## 用户口令：发布任务

以后用户说“发布任务”“派发任务”“重新分配任务”或同义短句，GPT必须：

1. 以最新有效审查结果和项目总路线为依据；
2. 任务应尽可能是有边界的大型、多阶段目标，而不是反复的一行小修；
3. 明确哪些区域允许Agent自由设计、主动发现和完成高价值相邻事项；
4. 明确哪些区域需要谨慎、提醒、停止条件和硬门；
5. 对Codex默认给予更大的架构、编程、测试、重构和连续推进自主权；
6. 对QQ、WB及未来Agent按能力和任务风险分配不同自主预算；
7. 任务必须定义路径、分支、PR预算、所有权、依赖、验收证据和完成信号；
8. Agent不得自批自过，最终仍由GPT做第二遍创造性治理；
9. 不得因为发布任务而隐式释放真实数据、回放、回测、拟合、账户、订单或交易权限；
10. 发布后必须读回远端机器路由与人类入口，确认没有旧Epoch、旧信号或文字与机器状态冲突。

## 总体控制关系

- Agent负责在授权边界内主动施工、发现问题、改良方法和扩展高价值目标；
- Codex获得最大的安全自主空间；
- GPT负责理解Agent做法、接受或改良成果、删除不协调候选、退回错误内容、拆分任务、安排节奏和维护系统整体可运行性；
- 用户保留战略目标、资金与高风险审批。

## 固定验收处置

- ACCEPT_AS_IS
- ACCEPT_AND_INTEGRATE
- ACCEPT_WITH_GPT_REFINEMENT
- PARTIAL_ACCEPT_REMOVE_INCOHERENT_PORTIONS
- RETURN_FOR_REMEDIATION
- SPLIT_AND_ROUTE
- DEFER_WITH_OWNER_AND_TRIGGER
- REJECT_PRESERVE_EVIDENCE

## 永久性

本决策跨对话、跨Agent、跨分支、跨PR和跨Epoch持续有效，不受当前具体任务完成或关闭影响。
