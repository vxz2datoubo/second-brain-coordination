# System of Record and Data-flow Map

| Object class | System of record | D0 role | D0 must not do |
| --- | --- | --- | --- |
| Source, evidence, knowledge, relation, decision, forecast, evolution | `brain_core.contracts` and its governed storage | Reference and link future candidate artifacts | Redefine or replace owner objects |
| Data lineage, quality, capability, adapters | `foundation_data_governance` | Constrain available observations and rule out unsupported inference | Add a live adapter or elevate a capability |
| Research replay, validation, journal | `trading_domain` | Future validation consumer | Rebuild replay or claim validation output |
| Local runtime/data facts | WorkBuddy evidence and approved manifests | Input boundary only | Overwrite or infer local facts |
| Candidate knowledge digestion | QCLAW package after acceptance | Reserved integration slot | Consume unaccepted output |
| Multi-agent hypotheses and plans | This D0 package, candidate-only | Defines interfaces and gates | Store authority facts, real identities or orders |

Future flow: governed observation -> evidence lineage -> latent hypothesis set -> candidate action/advantage/mismatch scenarios -> existing validation request -> candidate learning and review. Every arrow carries time, source, capability, rule and UNKNOWN state.
