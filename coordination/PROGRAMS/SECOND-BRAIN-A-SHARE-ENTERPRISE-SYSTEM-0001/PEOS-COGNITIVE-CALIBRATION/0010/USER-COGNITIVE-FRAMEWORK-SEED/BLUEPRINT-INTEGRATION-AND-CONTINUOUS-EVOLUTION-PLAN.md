## 1. 用户决定

用户希望把“个人认知框架”正式纳入 PEOS/W10 的长期蓝图方向，使未来系统能够持续回答：

- 用户当前在哪些领域已经形成认知；
- 每项认知掌握到什么层级；
- 哪些思维和能力表现较强；
- 哪些地方存在术语、证据、形式化、迁移、反例、校准或执行缺口；
- 哪些属于已知未知和未知未知；
- 后续对话、学习、任务和复盘怎样持续更新认知地图；
- 系统怎样基于认知框架提供学习、点拨、决策支持和能力调用。

同时，用户明确要求：

1. 将此方向加入蓝图和后续执行入口；
2. 不打乱 Codex、WorkBuddy 当前任务、优先级、节奏和资源分配；
3. 不立即启动大规模实现；
4. 未来由 Codex 与 WorkBuddy 按正式蓝图和治理流程落实与扩充；
5. QCLAW 只承担知识学习、研究消化和学习材料支持，不承担本系统的工程实现或运行时所有权。

## 2. 融合原则

### 2.1 不新建平行系统

个人认知框架必须成为以下现有能力的一个纵向切片，而不是独立产品：

```text
W3 知识与证据权威
→ W10 PersonalCognitiveModel
→ W10 MetacognitiveAuditAndGovernance
→ W10 LearningAndTransfer
→ W9 结果校准与工程学习
```

不得新建：

- 第二套长期记忆数据库；
- 第二套知识图谱事实源；
- 第二套个人画像运行时；
- 绕过 Knowledge Gateway 的聊天直写通道；
- 未经用户复审的自动永久画像。

### 2.2 蓝图先行，运行时后置

当前文件只冻结：

- 目标；
- 数据对象；
- Agent 分工；
- 演化闭环；
- 验收门；
- 与既有蓝图的映射候选。

正式 schema、接口、数据库、检索服务和 UI 必须等待现有企业级权威与共享接口完成相应冻结，再由 Codex 编制有界执行计划。

### 2.3 不抢占当前执行节奏

本方向登记为：

`QUEUED_BLUEPRINT_INPUT / NON_BLOCKING / NO_WIP_EXPANSION`

含义：

- 不替换当前 active task；
- 不要求 Codex 或 WorkBuddy 中断已有任务；
- 不自动创建新的并行实现线路；
- 不因本文件存在而提升模块成熟度；
- 只有在现有依赖、资源和治理条件满足时，才进入正式规划或实现。

## 3. 建议写回 PEOS 蓝图的能力

以下内容应在未来蓝图修订时纳入 `PersonalCognitiveModel`、`LearningAndTransfer` 和长期记忆章节。

### 3.1 CognitiveMap

用于描述用户认知结构的可版本化视图：

```text
领域
→ 概念与框架
→ 当前掌握度
→ 支持证据与反向证据
→ 适用情境与失效条件
→ 相关强项、缺口和 UNKNOWN
→ 学习任务与验证结果
```

CognitiveMap 是派生视图，可重建；事实源仍是原始证据、知识原子、用户纠正和正式验证记录。

### 3.2 MasteryAndTransferProfile

对每项知识或能力使用现有掌握阶梯：

`UNKNOWN → HEARD_OF → RECOGNIZES → CAN_EXPLAIN → CAN_APPLY_WITH_SUPPORT → CAN_APPLY_INDEPENDENTLY → CAN_TRANSFER → CAN_CRITIQUE → CAN_TEACH → CALIBRATED_MASTERY`

新增要求：

- 掌握度必须有任务证据；
- 能解释不等于能应用；
- 能应用不等于能迁移；
- 一次成功不等于稳定能力；
- 高掌握度必须知道边界、反例和失效条件；
- 用户自评与真实表现分别保存。

### 3.3 CognitiveGapRegistry

至少区分：

- `TERMINOLOGY_GAP`：已有直觉，缺正式术语；
- `FORMALIZATION_GAP`：能口头说明，不能建模或量化；
- `EVIDENCE_GAP`：缺少可靠证据；
- `TRANSFER_GAP`：换情境后不能稳定使用；
- `COUNTEREXAMPLE_GAP`：不能识别反例和失效条件；
- `CALIBRATION_GAP`：自信与表现不匹配；
- `EXECUTION_GAP`：知道方法但不能稳定执行；
- `UNKNOWN_UNKNOWN_CANDIDATE`：由对话、失败或反例暴露的新盲区。

### 3.4 MetacognitivePromptContract

在非简单问答中，系统可根据任务风险和用户偏好提供：

- 对应术语；
- 隐藏前提；
- 最强反方；
- 适用边界；
- 证据等级；
- 相邻理论；
- 形式化路径；
- 未知未知提示；
- 下一步最小学习或验证任务。

该合同不是要求每次都输出九项清单。系统应按情境自然选择，避免把普通对话变成模板化审讯。

### 3.5 CognitiveEvolutionEpisode

未来每次重要认知变化应形成一个可追溯事件：

```text
原始观点或任务
→ 当时知识与置信度
→ 新证据、术语、反例或失败
→ 用户如何修正判断
→ 掌握度是否变化
→ 新增或关闭哪些 UNKNOWN
→ 能否迁移到新领域
→ 下一次复审条件
```

这使系统记录的不只是“用户相信什么”，还包括“用户怎样改变了认知”。

## 4. 持续改进闭环

### 4.1 输入来源

- 用户与 AI 的严肃讨论；
- 用户显式记忆采集；
- 学习任务；
- 项目工作；
- 决策日志与复盘；
- 用户纠正；
- 真实结果和反例；
- 经授权的文件和本地资料。

### 4.2 处理闭环

```text
采集
→ 情境分类
→ 原子化观点、证据、假设、反例和未知
→ 检索历史认知与冲突
→ 生成 Observation / Gap / Mastery Candidate
→ 用户复审
→ 写入版本化模型
→ 生成学习或验证任务
→ 新结果回流
→ 修正、衰减、升级或撤销
```

### 4.3 双环学习

系统不仅修正具体结论，还应检查产生结论的方法。

- 单环：这次答案或决策哪里错了；
- 双环：用于判断的目标、假设、指标、证据门和工作流程是否需要修改。

### 4.4 周期性维护

未来运行时建议支持：

- 每次会话：只生成候选观察；
- 每周或达到阈值：聚合同类观察；
- 每月：复审高价值能力、缺口和 UNKNOWN；
- 每季度：检查跨领域迁移和陈旧认知；
- 重大失败或用户纠正后：立即触发局部重评；
- 长期无支持：自动标记 `STALE / REVIEW_REQUIRED`，而不是永久保留。

周期只是默认候选，正式实现应允许用户配置并根据实际使用频率调整。

## 5. Codex 职责

Codex 是未来工程设计和 canonical 实现的主要负责人。只有在正式激活后，Codex 才执行：

1. 对 Issue #38/#59/#60/#61/#63/#72 做非重复建设审计；
2. 把本种子对象映射到正式 canonical schema；
3. 冻结 `CognitiveObservation / CognitiveGap / Mastery / Unknown / UserCorrection / CognitiveEvolutionEpisode` 合同；
4. 定义版本迁移、数据校验、权限、失效和撤销语义；
5. 接入现有知识网关、证据图和长期记忆检索；
6. 建立 API、服务边界和测试合同；
7. 防止状态/特质混淆、角色扮演污染和模型自证循环；
8. 提供有界项目计划，不允许一次性扩张成万能数字分身。

Codex 不应：

- 直接依据本次聊天实现永久画像；
- 在共享接口冻结前创建平行运行时；
- 为赶进度绕过用户复审和证据门；
- 抢占当前 active route 或自行扩大 WIP。

## 6. WorkBuddy 职责

WorkBuddy 是未来本地集成、真实数据路径、运行验证和可用性落地的主要负责人。正式激活后可执行：

1. 盘点本地可授权数据源和格式；
2. 建立私有原始证据与公开抽象数据的隔离；
3. 验证聊天、文件、学习记录和复盘记录的导入；
4. 测试混合检索的真实召回、时间版本和撤销效果；
5. 建立本地隐私、备份、恢复、日志和可观测性；
6. 验证用户查看、纠正、冻结和撤销认知记录的界面流程；
7. 运行集成测试、负向测试和数据泄漏测试；
8. 把运行事实、失败和限制回报给 Codex 与 GPT，不自行修改 canonical 语义。

WorkBuddy 不应：

- 把私人原始对话上传到公开仓库；
- 在接口未冻结时自行发明第二套 schema；
- 把检索相似度当作事实真实性；
- 在没有用户批准时扩大数据采集范围；
- 打乱当前已分配任务和执行节奏。

## 7. QCLAW 的限定角色

QCLAW 只负责**学习知识与研究支持**，不负责个人认知框架系统的工程实施。

允许：

- 消化系统论、控制论、学习科学、元认知和用户模型研究；
- 提供术语解释、研究证据、反例和课程材料；
- 为学习 Backlog 生成候选知识原子；
- 指出某项学习材料的证据强弱和适用边界。

禁止：

- 担任本系统 implementation owner；
- 创建或修改个人认知框架运行时；
- 冻结 canonical schema 或接口；
- 控制用户画像升级、撤销或权限；
- 直接把知识消化结果写成用户稳定特质；
- 与 Codex 或 WorkBuddy 并行建设重复系统。

## 8. GPT 与用户职责

### GPT

- 在对话中进行自然的认知点拨；
- 提炼候选观察、缺口、术语、反例和 UNKNOWN；
- 保留不确定性，避免谄媚式画像；
- 编排用户复审；
- 审计 Codex/WB 的设计是否符合用户真实目标；
- 在重大扩展前做第二遍反向审视和验收。

### 用户

- 决定哪些内容值得长期记录；
- 接受、纠正、争议、冻结或撤销认知记录；
- 决定私人数据授权和公开范围；
- 决定学习优先级和实际用途；
- 批准高风险扩展。

## 9. 分阶段实施候选

### E0：蓝图登记

当前阶段。

交付：

- 目标和边界；
- 对象候选；
- Agent 分工；
- 持续演化闭环；
- 非抢占式激活规则。

状态：`READY_AS_BLUEPRINT_INPUT`。

### E1：非重复建设审计

触发条件：现有企业级共享接口和当前优先任务允许。

负责人：`CODEX`。

输出：本种子字段与 W3/W10/W9 现有合同的映射、复用和缺口表。

### E2：最小数据合同

负责人：`CODEX`，WB 提供真实格式反馈。

只实现：Observation、Mastery、Gap、Unknown、UserCorrection 和来源追踪。

### E3：只读认知地图

负责人：`CODEX + WORKBUDDY`。

能力：查看主题、掌握度、缺口、UNKNOWN、证据、时间和用户纠正状态。

此阶段不自动改画像。

### E4：受控更新闭环

负责人：`CODEX + WORKBUDDY`。

能力：候选生成、用户确认、版本更新、冲突保留、过期与撤销。

### E5：学习与迁移

负责人：`CODEX + WORKBUDDY`；QCLAW 仅提供学习材料和研究支持。

能力：根据缺口生成任务，记录完成结果，验证能否迁移到新情境。

### E6：认知点拨与任务辅助

能力：在不同任务中调用已验证强项、提示高风险缺口，并控制提示强度。

### E7：长期评测和演化

评测：错误画像率、状态/特质混淆、反证覆盖、用户纠正延迟、UNKNOWN 召回、跨域迁移、陈旧泄漏、隐私泄漏和实际学习增益。

## 10. 激活与节奏控制

本方向不得通过普通文档提交自动激活。进入任一工程阶段前必须满足：

1. 当前 active route 已按现有计划结束或释放资源；
2. 上游权威和接口达到该阶段需要的成熟度；
3. GPT 完成非重复建设和风险审查；
4. 用户确认本阶段目标和数据边界；
5. Codex 给出有界任务包、依赖、验收和回滚方案；
6. WorkBuddy 仅在接口明确后开始真实集成；
7. 不同时启动多个平行认知模型消费者。

优先级原则：

```text
先完成原有计划
→ 在自然排期点做非重复审计
→ 复用现有能力
→ 从只读、可纠正的最小切片开始
→ 验证后再扩充
```

## 12. 验收门

未来实施至少满足：

- 不形成平行运行时；
- 不打乱现有任务排期；
- 不把一次聊天变成永久特质；
- 不把模型推断冒充证据；
- 用户可查看、纠正、争议、冻结和撤销；
- 支持反证、冲突、UNKNOWN、时间和版本；
- 公开与私有数据严格分离；
- 学习效果和迁移能力可验证；
- Codex 和 WorkBuddy 职责清晰且不互相篡改权威；
- QCLAW 不承担实现或运行时所有权；
- 任何升级都通过原有治理速度和节奏推进。
