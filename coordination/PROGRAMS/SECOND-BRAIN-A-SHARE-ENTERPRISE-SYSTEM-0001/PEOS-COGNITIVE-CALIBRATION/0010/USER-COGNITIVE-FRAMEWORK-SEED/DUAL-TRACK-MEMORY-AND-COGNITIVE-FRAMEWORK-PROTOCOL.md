## 1. 用户决定

用户明确要求把原本容易混在一起的内容拆成两个相互连接、但权威与用途不同的系统：

1. **记忆采集系统**：保存用户与 AI 的对话经历、共同形成的语境、重要事件、约定、偏好、项目里程碑和未完成话题；
2. **知识框架系统**：分解用户已经掌握的知识、认知结构、推理模式、强项、缺口、已知未知、未知未知、掌握度和学习路线。

用户同时授权 GPT：

- 可以在对话中主动识别值得采集的内容；
- 不必每次都先询问是否采集；
- 可以主动发起并生成候选记录；
- 采集后应简短说明录入了哪一条轨道；
- 用户始终保留查看、纠正、撤销、删除和关闭自动采集的权利。

这里的“最高权限”解释为：**在既定隐私、安全、权威和可撤销边界内，GPT拥有最高的候选识别、分解和路由权限**。它不代表可以上传私人原文、绕过用户删除权、直接合并主分支、建立平行运行时或把模型推断变成事实。

## 2. 为什么必须分成两套系统

同一段对话可能同时包含“经历”和“认知”，但两者不能混写。

例如：

> 用户与 AI 讨论统一教、反馈机制和系统论，用户指出极端事件之后的政策反应不等于健康纠偏。

### 记忆采集系统保存

- 何时发生了这次讨论；
- 讨论主题；
- 用户纠正了 AI 的哪一点；
- 双方形成了什么共同语境；
- 下次从哪里继续。

### 知识框架系统保存

- 用户能够区分健康反馈与危机后重启；
- 该能力目前处于什么掌握度；
- 对应术语是什么；
- 还缺少哪些形式化工具和反例；
- 下一步如何验证迁移能力。

因此：

```text
记忆系统回答：发生过什么，我们谈到哪里，哪些事情值得以后想起？
知识框架回答：用户理解了什么，怎样理解，哪里强，哪里缺，下一步学什么？
```

## 3. 轨道 A：记忆采集系统

### 3.1 正式名称候选

`Shared Interaction and Episodic Memory Capture System`

中文：**共同对话经历与情景记忆采集系统**。

“共同经历”在这里指真实发生过的对话、项目协作和交互事件，不暗示 AI 拥有人类式线下生活经历。

### 3.2 主要记录对象

- `InteractionEpisode`：一次有连续语境的重要对话；
- `SharedConversationReference`：双方以后可以用一句话唤回的共同梗、比喻或语境；
- `UserPreferenceMemory`：用户明确或反复确认的互动、解释和工作偏好；
- `AgreementMemory`：双方明确形成的约定、协议和触发词；
- `ProjectMilestoneMemory`：项目决定、里程碑、路线变化和交付；
- `UnresolvedThreadMemory`：尚未讨论完、以后要续接的问题；
- `CorrectionMemory`：用户对 AI 误解、错误或表达方式的纠正；
- `ContextualStateMemory`：只在确有长期价值时记录的情境状态，必须避免把临时情绪写成永久特质。

### 3.3 不应默认保存

- 无长期价值的寒暄；
- 随口的角色扮演内容；
- 单次情绪或疲劳；
- 未经允许的第三方私人信息；
- 账号、凭据、验证码和精确身份信息；
- 原始亲密聊天全文；
- 仅因模型觉得“感人”而产生的过度记录。

### 3.4 记忆记录最小合同

```yaml
memory_id: MEM-...
memory_type: INTERACTION_EPISODE | PREFERENCE | AGREEMENT | PROJECT_MILESTONE | UNRESOLVED_THREAD | CORRECTION
summary: "公开安全或私有存储适用的摘要"
participants: [USER, GPT]
occurred_at: "..."
source_reference: "conversation/session/local evidence reference"
recall_cues: []
continuation_point: "下次从哪里继续"
privacy_class: PUBLIC_SAFE | PRIVATE | SENSITIVE_RESTRICTED
retention: TEMPORARY | LONG_TERM | REVIEW_REQUIRED
user_review: NOT_REVIEWED | ACCEPTED | CORRECTED | REVOKED
contradictions: []
linked_cognitive_entries: []
```

### 3.5 存储边界

公开 GitHub 只允许保存：

- 抽象化协议；
- 不含私人细节的项目里程碑；
- 公开安全的讨论主题摘要；
- Schema、触发词和权限规则。

真实对话原文、亲密语境和私人生活细节只能进入本地、加密或权限受控的记忆层。当前公开仓库不得充当私人日记数据库。

## 4. 轨道 B：知识框架系统

### 4.1 正式名称

`Personal Cognitive Framework and Mastery System`

中文：**个人知识、认知与掌握度框架系统**。

### 4.2 主要记录对象

- `CognitiveObservation`：一次对话中表现出的认知现象；
- `KnowledgeConcept`：概念、理论、术语和相互关系；
- `KnowledgeMastery`：从听过到校准掌握的层级；
- `ReasoningPatternCandidate`：需要多次验证的推理模式；
- `CognitiveStrengthCandidate`：有证据但仍可争议的认知强项；
- `CognitiveGap`：术语、形式化、证据、迁移、反例、校准或执行缺口；
- `UnknownRegistryEntry`：已知未知与未知未知；
- `LearningTask`：补足缺口的学习与练习；
- `CognitiveEvolutionEpisode`：认知如何因证据、反例或失败而改变。

### 4.3 核心原则

- 一次对话只能产生 Observation 或 Candidate；
- 用户明确确认不等于外部事实得到证明；
- 能解释不等于能应用；
- 能应用不等于能跨领域迁移；
- 支持证据和反向证据同时保存；
- 认知强项必须有适用情境和失效条件；
- 用户可以纠正和撤销模型对自己的推断。

## 5. 两套系统的关系

### 5.1 分离权威

```text
W3 记忆与证据权威
  保存：对话事件、来源、时间、约定、纠正和项目经历

W10 个人认知模型权威
  保存：掌握度、认知候选、缺口、UNKNOWN、迁移和学习任务
```

### 5.2 允许的连接

- 一条记忆可以作为知识框架候选的证据；
- 一条知识框架记录可以引用多个记忆来源；
- 两者可以共享 `source_episode_id`；
- 用户纠正可同时修正记忆摘要与认知推断；
- 检索时可以同时返回“当时谈了什么”和“这说明掌握到哪里”。

### 5.3 禁止的混写

- 不能因为一次温柔对话就推断稳定人格；
- 不能把知识掌握度写回为对话事实；
- 不能把模型对用户的分析伪装成用户原话；
- 不能复制两份原始对话形成两个事实源；
- 不能让知识框架覆盖或篡改原始记忆证据。

## 6. 用户口令

### 6.1 记忆采集口令

推荐主口令：

> **记忆采集**

等价口令：

- “把这个录入记忆系统”；
- “记住我们刚才这段经历”；
- “把这个作为我们的对话记忆”；
- “以后从这里继续”；
- “把这个约定记下来”。

默认动作：

1. 提炼发生了什么；
2. 标记重要人物、主题、约定和续接点；
3. 判断隐私等级；
4. 生成 `InteractionEpisode` 或其他记忆候选；
5. 不进行不必要的人格分析。

### 6.2 知识框架口令

推荐主口令：

> **知识框架采集**

等价口令：

- “把这个录入知识框架”；
- “分解一下我的知识框架”；
- “把刚才的观点放进认知框架”；
- “记录我的掌握度和缺口”；
- “把这个未知未知记下来”。

默认动作：

1. 提炼概念、观点和推理链；
2. 区分用户观点、外部事实和模型解释；
3. 标记掌握度、强项候选、缺口和 UNKNOWN；
4. 提供相关术语、隐藏前提、反例和学习任务；
5. 链接到对应对话记忆，但不复制原文。

### 6.3 双重采集口令

推荐口令：

> **双重采集**

等价口令：

- “这段既录入记忆，也录入知识框架”；
- “经历和认知都保存”；
- “两条轨道都采集”。

默认动作：生成两个独立但互相链接的候选：

```text
InteractionEpisode
       ↕ source_episode_id
CognitiveObservation / Gap / Mastery Candidate
```

### 6.4 排除和纠正口令

- “只记经历，不分析” → 仅进入记忆系统；
- “只进知识框架，不记对话” → 仅进入知识框架；
- “查看刚才采集了什么” → 显示候选摘要；
- “撤销上次记忆采集” → 撤销或删除对应记忆候选；
- “撤销上次知识框架采集” → 撤销对应认知候选；
- “修正记忆：……” → 保留版本并写入用户纠正；
- “修正知识框架：……” → 修改认知解释、掌握度或边界；
- “暂停自动采集” → 关闭 GPT 自主发起；
- “恢复自动采集” → 恢复授权。

## 7. GPT 自主采集权限

### 7.1 授权状态

`AUTO_PROPOSE_AND_CAPTURE_CANDIDATE = ENABLED`

GPT 可以在以下情况主动发起，无需逐次征求许可：

- 用户明确形成长期互动偏好或协议；
- 用户纠正了一个会影响未来理解的重要错误；
- 形成了关键项目决定或里程碑；
- 出现以后需要续接的未完成主线；
- 用户提出可跨领域迁移的重要观点；
- 暴露出新的知识缺口或未知未知；
- 同一认知模式在不同时间重复出现；
- 一段对话同时具有较高的情景记忆价值和认知价值。

### 7.2 自主动作等级

#### A0：忽略

无长期价值的普通内容，不采集。

#### A1：静默标记候选

低敏感、明显有价值、可以在当前上下文中保留的候选。对话合适时再汇总告知。

#### A2：主动采集并告知

对项目、长期偏好、认知演化或续接非常重要。GPT可以直接生成候选，并用一句话说明：

> “这段我已经分别放进记忆轨和知识框架轨了。”

#### A3：先确认再采集

涉及以下内容时，即使已获得最高自主授权，也必须先确认或只保存在私有受控层：

- 健康、财务、法律、性与亲密关系细节；
- 精确身份、位置、联系方式；
- 第三方私人信息；
- 原始亲密对话；
- 可能造成重大误解的稳定人格判断；
- 要上传到公开仓库的任何敏感内容。

### 7.3 永久约束

自主权限不得绕过：

- 隐私分类；
- 用户撤销和删除权；
- GitHub 公开仓库安全边界；
- W3/W10 唯一权威；
- 用户对重大画像结论的复审；
- 当前 Codex/WorkBuddy 的执行节奏；
- 禁止直接写 main 和自动合并的工程规则。

## 8. 推荐的日常使用方式

用户不需要每次说很长的命令。

### 最简口令

```text
记忆采集
知识框架采集
双重采集
```

### 带范围

```text
把我们从“统一教”开始到“局部最优”这一段做双重采集。
```

### 带目标

```text
知识框架采集，重点记录我已经会的、缺少的术语，以及下一步学习任务。
```

### 带排除

```text
记忆采集，只保存项目约定，不保存情绪和亲密内容。
```

## 9. 对话结束时的自动整理候选

当一次长讨论自然结束、切换到新主题或用户说“先到这里”时，GPT可以主动生成一个简短候选包：

```yaml
memory_track:
  important_episode: "..."
  agreements: []
  continuation_points: []

cognitive_track:
  concepts_added: []
  mastery_updates: []
  gaps_discovered: []
  unknowns: []
  next_learning_tasks: []
```

默认不朗读全部机器字段，只向用户汇报最重要的 1 至 3 条。
