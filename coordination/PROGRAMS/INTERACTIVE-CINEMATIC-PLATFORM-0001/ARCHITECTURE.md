# 互动电影平台架构基线

`INTERACTIVE-CINEMATIC-PLATFORM-0001` 是一个**私有优先、文字驱动、可回放**的互动电影平台。GitHub 只保存合成测试、契约、哈希、审批状态与脱敏收据；它不是用户媒体库、凭证库或运营数据库。

## 1. 用户可感知的产品闭环

```text
玩家文字 / 已授权评论文本
  -> Intake 记录来源、去重和等待状态
  -> ChoiceIntent/v1（不是直接改剧情）
  -> NarrativeProposal/v1（模型只提出候选）
  -> 规则验证器 + 戏剧管理器 + 状态机
  -> 已验证的 NarrativeState/v1 和追加式账本
  -> DirectorBrief/v2 + ShotBundle/v1
  -> CinematicSegment/v1 + MediaJob/v1
  -> 离线确定性媒体结果（当前）/ 经单独批准的外部结果（未来）
  -> 片段、奖励、队友反馈与下一次选择
```

一个主选择必须让线索、关系、装备或资源、风险、任务、场景、结局路径中至少一项产生可回放的实际差异。戏剧管理器只能从**已批准节拍**中选择，不得篡改玩家事实、代替玩家选择，或把未验证模型输出写入账本。

## 2. 共享内容与玩家私有状态

```text
不可变共享内容（可版本化）              每位玩家的独立增量状态（私有）
ScriptPackage/v1                         PlayerCampaign/v1
CharacterBible/v1                        append-only event ledger
SceneBible / StyleProfile                snapshots at scene boundary or each 8 actions
approved asset manifest                  reward / relationship / quest delta
                                         avatar revision references
                                         private media references and consent revision
```

同一剧本的多个玩家只引用同一个 `script_id + script_revision`，不会复制整季内容。玩家账本以事件增量和快照保存，重放从最近快照加后续事件恢复；这优先保证结果正确，同时避免重复存储整个剧情。私有媒体缓存的键必须包含玩家/campaign/头像版本，禁止跨玩家命中。

## 3. 六个模块及边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 内容与剧本 | 已批准故事、人物、场景、规则、风格和资产清单 | 直接改玩家账本或调用媒体供应商 |
| 互动与戏剧管理 | 意图解析、候选校验、节拍选择、奖励和状态转换 | 把模型候选直接当事实 |
| 私有外貌与资产 | 头像身份/版本、角色定妆锚点、连续性引用 | 将照片、特征或媒体写入 GitHub |
| AI 导演与媒体 | 导演稿、镜头束、媒体任务、质量门 | 决定剧情真相或绕开内容边界 |
| 运营与抖音 | 人工入口、评论模拟、去重、能力门、人工回退 | 假定评论图片已获得稳定授权 |
| 第二大脑 | 只记录候选、纠正和人工审批 | 自动把玩家偏好升格为正式创作规则 |

## 4. 剧本、风格与导演

首季约束为冒险 × 悬疑 × 犯罪 × 情感，目标 45–60 分钟、三幕六章、十二个主选择点。电影真人为主风格；风格化 3D、日式动画和水墨动画只能改变表达方式，不得改变已验证的故事事实、角色身份、服装、伤势、道具、空间或镜头职责。

每次导演编译必须带上：`script_id`、`script_revision`、`campaign_id`、`verified_story_state_hash`、`style_profile_id`、`cast_revision_ids`、`scene_asset_refs`、`continuity_ledger_hash`、`director_policy_revision`。缺少任一字段即不产生外部媒体任务。

DeepSeek 的职责是产生结构化 `NarrativeProposal/v1`；它不能自行改变状态。MiniMax H3 的未来职责是生成 4–15 秒的短视听段。整季是经过连续性检查的一系列片段，绝不是每轮留言生成一部无边界长片。当前唯一允许的适配器是离线确定性模拟器。

## 5. 外貌、隐私与连续性

首次经批准的本地私有照片建立 `AvatarIdentity/v1`。只有明确命令 `整容 + 指定角色 + 新图片` 才产生 `AvatarRevision/v1`；新版本只从批准后的后续剧情生效，历史片段不被静默重写。NPC 在首次正式登场前应有已批准的角色外观锚点。GitHub 只保存 ID、不可逆引用哈希、同意版本和审核状态，绝不保存原图、面部特征或真实媒体。

## 6. 抖音入口与人工回退

评论文字先进入 `DouyinCommentIngest/v1`，去重后转为意图。评论图片必须先经过 `DouyinImageCapabilityGate/v1`：官方评论列表文档没有承诺稳定的评论附图字段，并且数据访问取决于权限与授权。因此图片能力未正式通过时：文字剧情继续，系统为运营者建立人工导图通知，玩家会话保持可恢复的等待状态。

## 7. 安全、证据与协作

- `main` 只接受有精确 HEAD、可重跑命令、交接包、独立复核和用户明确合并授权的 PR。
- Codex 只能声明 `EXECUTOR_VERIFIED_ONLY`；未参与实现的 GPT 才能记录独立验算。
- 真实供应商、付费生成、抖音实接、公开发布、部署、账户、凭证、真实评论与个人照片均不属于 A0–A4。
- Eustia 不是默认输入，也不在本次架构中导入；它必须先通过独立来源、版权、内容与资产审查，才可作为私有剧本包候选。
- 第二大脑的候选与正式知识严格隔离。生成结果、玩家偏好或模型输出不得回写历史剧情事实。

## 8. 证据基础与待验证假设

- 有意义选择规则参考 `Foreseeing Meaningful Choices`（AAAI 2014）的可观察后果思想，并在 A2 以 100% 主选择状态差异覆盖测试，不把论文结论当作本项目的用户数据。
- 戏剧管理器的“候选、约束、节拍选择”边界借鉴 drama-management 研究；具体节拍效果仍以人工评审和后续脱敏指标验证。
- 视觉连续性以角色锚点、服装/道具/伤势、空间、情绪和镜头责任账本表达；A3 才实作质量报告。
- 真实平台能力、生成质量、延迟、成本和留存属于尚未知现实变量，必须在用户批准的私有试点中测量。
