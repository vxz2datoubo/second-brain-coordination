## Fresh-session stable entrypoints

For a new GPT architecture/project window:

- `coordination/GPT-ARCHITECTURE-START-HERE.md`

For a new WorkBuddy engineering session:

- `coordination/WORKBUDDY-ENGINEERING-START-HERE.md`

Canonical engineering operating mode:

- `coordination/GOVERNANCE/GPT-WORKBUDDY-ENGINEERING-OPERATING-MODE-v1.0.yaml`
- `coordination/GOVERNANCE/GPT-WORKBUDDY-ENGINEERING-INTERFACE-SCHEMAS-v1.0.yaml`

Default chain:

`Owner -> GPT Architecture/Governance -> GitHub task truth -> WorkBuddy local implementation/test -> GitHub PR/exact-head CI -> separate GPT independent review -> separate canonicalization -> main`

These entrypoints are navigation/bootstrap only. Actual execution authority still comes from the current governed task route/claim/lease/snapshot and active task truth.
